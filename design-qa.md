# Design QA: Terminal WarpText

## Comparison Target

- Source visual truth: user request for a centered, oversized `奶娃` terminal mark using the React Bits WarpText configuration; a prior terminal screenshot showed the rejected right-aligned, undersized baseline.
- Implementation: `http://127.0.0.1:5178/` terminal state in the local Vite app.
- Target viewport: desktop `1280 x 720` CSS pixels, device scale factor unavailable from the in-app browser.
- Captured implementation evidence: `qa-iab-loading.png`.

## Required Fidelity Surfaces

- Fonts and typography: code uses the existing rounded `--display` stack and the registry configuration `fontSize: clamp(3rem, 10vw, 9rem)`, `fontWeight: 800`, with a fixed `320px` canvas height.
- Spacing and layout rhythm: `.terminal-mark` is positioned at `left: 50%` and GSAP applies `xPercent: -50`, replacing the former right-aligned layout.
- Colors and tokens: the WarpText texture uses the requested `#f8f5ff`; the surrounding terminal label stays in the existing muted yellow system.
- Image quality and asset fidelity: no raster or icon asset is required. The visible mark is generated by the React Bits text-texture shader.
- Copy and content: terminal copy remains `END STATE / 01` and `奶娃`.

## Findings

- [P1] Browser-rendered visual comparison is blocked.
  Location: local Three.js scene in the in-app browser.
  Evidence: the in-app browser remains at the existing `LOADING SPECIMEN` screen, and its environment cannot initialize the page's WebGL scene. The available Chrome browser connector is unavailable in this session.
  Impact: the exact desktop and mobile visual result, canvas output, and pointer distortion cannot be visually compared in this environment.
  Fix: open the local scene in a WebGL2-capable browser and inspect the release terminal state at desktop and mobile breakpoints.
